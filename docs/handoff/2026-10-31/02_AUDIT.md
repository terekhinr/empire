| Секреты | в git не класть. `.env` на диске есть как локальный файл |

Вывод: большая часть продукта (сайты, HA-пакеты октября, TTS, практикум, карьера) живёт в рабочем дереве и в бэкапе Диска, а не в аккуратной истории коммитов. Другому ИИ нельзя делать `git add -A` и один гигантский коммит. Нельзя `reset --hard`. Коммит — только по просьбе владельца и только по названным файлам.

## 6. Риски кода и эксплуатации

1. **Почти всё крутится от root** (`User=root` у юнитов). Падение или ошибка агента бьёт по прод-дереву напрямую. Задуманный режим из `docs/LOCAL_AI_RULES.md`: правка на ПК, на VPS только выкладка нужных файлов и рестарт одного юнита.
2. **Dual-run.** Один и тот же `empire_main` на двух VPS даст двойные посты. Front VDSina код не исполняет, origin — исполняет.
3. **`docker-compose.yml` в корне врёт о проде.** Там Postgres с паролем-заглушкой и контейнер Степаныча. Живые бани и бот — SQLite + systemd. Compose не поднимать «чтобы как в файле».
4. **Много входов задачника.** Любой новый URL ухудшает приёмку. Сначала выбрать один и проверить с телефона.
5. **Хилер может чинить шумно.** Правило из `docs/HEALER_ARCHITECTURE.md`: cooldown, не крутить restart пачкой. Flint: LKG, не шторм `podkop restart` (урок CP-20261022 — 15 дублей crontab уронили sing-box).
6. **Дашборд и home-ops** смотрят в дом. Секреты доступа: `docs/dashboard_access.md`. В чат не копировать.
7. **Android gradle-мусор** в статусе git (lock-файлы, apk). В коммит не тащить.
