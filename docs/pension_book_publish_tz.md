## 0. Ответ: что делать раньше — книгу, соцсети или сайт?

### Короткий ответ

**Не «сначала всё, потом книга» и не «сначала книга в вакууме».**  
Оптимально: **параллельно, но с разной глубиной по фазам** — один бренд, один домен, разный уровень готовности.

| Подход | Вердикт |
|--------|---------|
| Сначала только книга, потом соцсети и сайт | ❌ Launch без аудитории = почти нулевые продажи |
| Сначала соцсети и сайт «под книгу», книгу отложить | ❌ Контенту не на что ссылаться, воронка пустая |
| **Параллельно по матрице ниже** | ✅ Рекомендуется |

### Матрица «параллельно, но по слоям»

| Слой | Когда включать | Минимум на старте | Не ждать |
|------|----------------|-------------------|----------|
| **Сайт neverretire.ru** | Сразу | Главная, `/book` (введение + 1–2 главы), дисклеймер, ссылки на соцсети | Полную книгу, оплату |
| **Telegram Pension** | Уже есть | Сырые новости + редкие `[ANALYSIS]`; цитаты из черновика книги | Идеальный текст книги |
| **ВК + Дзен** | Через 1–2 нед. после стабилизации TG | Оформление, 5–10 постов, 1 статья Дзен | Launch книги |
| **YouTube** | После 2–3 нед. контента на сайте/Дзен | Оформление канала, выпуск №1 | Печать тиража |
| **Текст книги** | Сейчас (главный поток) | Черновик → правка → финал | Идеальные соцсети |
| **Оплата / PDF** | За 2–4 нед. до launch | `pay.neverretire.ru` + PDF | Маркетплейсы |
| **Самиздат (ЛитРес/Ridero)** | Неделя launch | EPUB + обложка | До beta-читателей |

### Правило 70/30 по времени (до launch)

- **70%** — довести текст и beta.  
- **20%** — сайт (бесплатные главы, email, метрика) + 2–3 поста в неделю из материала книги.  
- **10%** — оформление ВК/Дзен/YouTube (не ежедневный контент-завод).

**Launch книги** — когда одновременно: финальный PDF, страница покупки, 8+ недель «присутствия» в ленте (TG/ВК/Дзен), 3+ beta-отзыва.

## 1. Связь с сайтом neverretire.ru

### 1.1. Текущая реализация (код)

| Компонент | Путь / маршрут |
|-----------|----------------|
| Приложение | `web_app.py` — FastAPI, порт 8000 за nginx |
| Канонический домен | `neverretire.ru` (+ зеркала → 301 на канон) |
| Текст книги | `data/book/napensiyu_nikogda.json` |
| Оглавление | `GET /book` → `templates/book_toc.html` |
| Глава | `GET /book/{slug}` → `templates/book_chapter.html` |
| Главная (промо книги) | `GET /` → блок «книга» в `templates/index.html` |
| Статьи | `GET /articles`, `/articles/{id}` — `post_drafts`, `persona_key=pension`, `published` |
| Видео | `GET /videos` — `data/site/videos.json` |
| SEO | `/sitemap.xml`, `/robots.txt` — все главы книги в sitemap |
| Оплата (бэклог) | `pay.neverretire.ru` + `sales.db` + `empire_sales.py` |

### 1.2. Целевая структура сайта для воронки книги

```
neverretire.ru/
├── /                      — hero + CTA «читать введение» + email pre-launch
├── /book                  — оглавление (все главы; платные — пометка или paywall позже)
├── /book/introduction     — бесплатно всегда
├── /book/{slug}           — бесплатно: 1–2 главы; остальное — teaser + «купить PDF»
├── /buy                   — страница продажи (бэклог)
├── /articles              — лонгриды из Pension (Дзен-дубли)
├── /videos                — YouTube + UTM
└── /about                 — автор, дисклеймер, контакты
```

### 1.3. Задачи по сайту (бэклог кода)

| # | Задача | Приоритет |
|---|--------|-----------|
| S1 | Яндекс.Метрика: код на сайте ✅ — вам: `YANDEX_METRIKA_ID` в `.env` + цели в кабинете | P0 |
| S2 | UTM: единый шаблон ссылок в шаблонах/футере | P0 |
| S3 | Страница `/buy` + продукт `book_full` в `sales.db` | P1 (до launch) |
| S4 | Email pre-launch (форма → список; Cloudflare / внешний сервис) | P1 |
| S5 | Paywall или «читать N% главы» + кнопка покупки | P2 |
| S6 | Автовыдача PDF после оплаты ЮKassa | P1 |
| S7 | Webhook `empire_sales` + учёт НПД | P1 |

Документация Метрики (по аналогии с gdepar): `docs/metrika_setup_guide.md`, цели — §6 ниже.

### 1.4. Синхронизация контента

| Источник | Куда на сайте |
|----------|----------------|
| Финальный JSON книги | Обновить `data/book/napensiyu_nikogda.json` → деплой |
| Пост Pension `[ANALYSIS]` | После approve → `published` → `/articles/{id}` |
| Глава книги (адаптированная) | Статья в Дзен + краткий пост ВК; на сайте — не дублировать **полный** текст книги |
| YouTube | `data/site/videos.json` + embed на `/videos` |

**Правило:** в Дзен/TG — **фрагменты и углы**, на сайте `/book` — **чтение**, в PDF/магазине — **полная версия**.

### 2.1. Карточка продукта

| Поле | Значение |
|------|----------|

- Дисклеймер ИИР — на обложке, в PDF, в футере сайта (уже есть на сайте).

- Без обещаний доходности в рекламе и аннотации.
- Конкуренты (@pensiya35 и т.п.) — не упоминать (см. промпты Pension в `main.py`).

### 2.3. Лестница продуктов

```
Бесплатно: /book/introduction + 1 глава на сайте
    ↓
Lead: email «глава в подарок / уведомление о выходе»
    ↓
Tripwire: PDF 490–690 ₽ (сайт)
    ↓
Основной: полная книга 990–1490 ₽ (сайт) / 299–499 ₽ (ЛитРес)
    ↓
Позже: курс, консультация (не в день launch)
```

## 3. Пайплайн создания текста (Claude + человек)

### 3.1. Фазы текста

| Фаза | Содержание | Ответственный |
|------|------------|---------------|
| T1 | Черновик всех глав (Claude по брифу) | Claude + редактор |
| T2 | Структурная правка (вырезать/переставить) | Редактор |
| T3 | Второй проход Claude (сокращение, клише, крючки) | Claude + редактор |
| T4 | Стилистика и голос «Борода» | Редактор |
| T5 | Beta 5–15 читателей | Внешние |
| T6 | Копирайт + факты `[ПРОВЕРИТЬ]` | Редактор |
| T7 | Freeze → JSON → PDF/EPUB | Редактор + скрипт сборки |

### 3.2. Бриф на главу (шаблон для Claude)

```text
Книга: «На пенсию НИКОГДА», голос — резкий, ироничный, без инфобизнеса.
Глава: [номер, slug, название]
Цель главы: [одно предложение]
После главы читатель: [понимает / чувствует / делает]
Включить: [3–5 тезисов]
Запретить: доходность, копипасту, [конкурентов]
Объём: ~[N] знаков
Структура: [подзаголовки]
```

### 3.3. Промпты второго прохода Claude

- «Сократи до N знаков, сохрани тезисы: …»
- «Найди 10 клише, замени в том же тоне»
- «Вступление — крючок 120 слов»
- «Проверь: один вывод + одно действие в конце главы»

### 3.4. Только руками (не отдавать Claude)

- Личные истории (2–3 на книгу).
- Цифры с первоисточником (ЦБ, Росстат).
- Юридически спорные формулировки.
- Единый глоссарий (5–10 терминов).

### 3.5. Чеклист качества главы (перед freeze)

- [ ] Один главный тезис, не три конкурирующих
- [ ] Нет трёх подряд абзацев с одной метафорой
- [ ] Вывод + «что делать читателю» в конце
- [ ] Факты без непроверенных цифр
- [ ] Длина в пределах плана (±15%)
- [ ] Дисклеймер не нужен в каждой главе — только в начале книги и на обложке

## 6. Метрики: сайт, соцсети, продажи

### 6.1. Принцип

- **Сайт** — Метрика + цели `reachGoal` + UTM.  
- **Соцсети** — нативная статистика + UTM на сайт (единый источник истины для воронки).  
- **Продажи** — `sales.db` + ручная сводка маркетплейсов до интеграции.  
- **Empire** — `analytics.db` для событий TG/публикаций (по аналогии с gdepar).

### 6.2. Яндекс.Метрика — цели на neverretire.ru (создать в интерфейсе)

Тип цели: **JavaScript-событие**, идентификатор = имя события.

| Идентификатор | Когда срабатывает | Зачем |
|---------------|-------------------|-------|
| `pension_page_view` | Любая страница (опционально с page) | Базовый трафик |
| `pension_book_toc_open` | Открыт `/book` | Интерес к книге |
| `pension_book_chapter_read` | Прокрутка >70% главы или время >3 мин | Вовлечённость |
| `pension_book_cta_buy` | Клик «Купить книгу» | Намерение |
| `pension_email_submit` | Отправка pre-launch формы | Лид |
| `pension_buy_page_open` | Открыт `/buy` | Воронка |
| `pension_payment_start` | Клик «Оплатить» | Checkout |
| `pension_payment_success` | Return URL после ЮKassa | Продажа |
| `pension_article_read` | Статья, scroll >70% | Контент-маркетинг |
| `pension_video_play` | Старт embed на `/videos` | Видео-воронка |
| `pension_tg_click` | Клик «Telegram» в футере | Уход в TG |

**KPI сайта (формулы):**

| KPI | Формула |
|-----|---------|

| CR email→buy (позже) | покупки с меткой email-кампании / подписчики |
| Доля органики | Метрика → Источники → Поиск |

Env: `YANDEX_METRIKA_ID` (отдельный счётчик для neverretire, не путать с gdepar).
