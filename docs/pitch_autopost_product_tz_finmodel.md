## 1. Конкурентная карта (сводка)

| Игрок / класс | Модель | Чек | Сила | Слабость vs нас |
|---------------|--------|-----|------|-----------------|
| **Buffer** | Очередь «залил → ушло» | $6+/канал | Масса SMB, простота | Нет банка на квартал; нет VK/TG-ниши |
| **SocialBee** | Категории + evergreen-ротация | ~$29–99/мес | Ближайший аналог «настроил — крутится» | Нет тематического банка под нишу; западные сети |
| **Later** | Визуальный календарь | ~$25+/мес | IG/сетка | Не про TG-медиа |
| **Sprout / Hootsuite** | Suite: inbox + listening | $200+/seat | Enterprise-деньги | Другой покупатель |
| **SMMplanner / Postmypost / Onlypult** | RU-планировщик VK+TG | 900–3000 ₽/мес | Локальный дефолт | Клиент сам пишет посты каждый день |
| **LiveDune** | Аналитика + постинг | ~2900 ₽+ | Отчёты | Не «контент сам» |

**Вывод рынка:** платят за (1) простой планировщик и (2) **банк + ротацию**. AI-генерация — шум в обзорах, не ядро удержания.

**Наш зазор (не «ещё один SMMplanner»):**

```
Матрица слотов  +  банк готовых постов  +  жёсткий контракт «текст+картинка»
+ fallback из архива  +  аудит/алерты  →  квартал без ежедневного участия
```

Ближайший западный якорь позиционирования: **SocialBee**, не Buffer.  
Ближайший RU-конкурент по каналам: SMMplanner — мы **не бьём его шириной площадок**, а бьём **автономностью банка и нишевым наполнением**.

## 2. Удачная модель для продажи

### 2.1. Что продаём (не SaaS «на миллион пользователей»)

**Продукт:** «Издательство» — автономный автопост по матрице из готового банка.  
**Формат выхода на рынок:** **done-with-you / done-for-you сервис на своём софте**, затем лёгкий SaaS.

| Ступень | Что получает клиент | Цена-якорь | Зачем |
|---------|---------------------|------------|-------|
| **A. Setup** | Матрица + Studio + 1–2 канала + тест-неделя | **25–45 тыс ₽** разово | Быстрый кеш, валидация |
| **B. Банк 90 дней** | 90–180 готовых постов (текст+фото) под нишу | **40–90 тыс ₽** разово | Главная ценность / отличие |
| **C. Сопровождение** | Live + weekly audit + долив банка | **5–12 тыс ₽/мес** | Recurring |
| **D. White-label позже** | Свой бренд агентства на нашем движке | **от 15 тыс ₽/мес** | После 5–8 кейсов |

**Не продавать первым шагом:** чистый self-serve SaaS за 990 ₽/мес против SMMplanner — CAC съест всё, банк контента клиент не заполнит сам → churn.

### 2.2. Ideal customer

1. Владелец 1–3 TG/VK-каналов в узкой теме (баня, сад, спорт, экспертный блог).  
2. Агентство на 3–10 клиентов, которому нужен «канал живой без копирайтера каждый день».  
3. **Не** enterprise с listening; **не** блогер, которому нужен только IG-grid.

### 2.3. Обещание на лендинге (одна фраза)

> Один раз настраиваем матрицу и банк постов. Дальше канал постит сам 90 дней: текст + картинка по правилам, без ИИ в эфире и без вашего ежедневного участия.

### 2.4. Почему эта модель удачная

- Деньги с **Setup + Банк** до того, как SaaS «взлетит».  
- Используем уже написанный Empire-стек → CAPEX низкий.  
- Контент-банк — барьер, который SMMplanner не закрывает.  
- Можно пилотить на своих 5 каналах как витрину.

## 4. Техническое задание (MVP «Издательство Pro»)

### 4.1. Цель

Продукт для продажи: клиент один раз настраивает каналы, матрицу и банк постов; система публикует по расписанию **без ИИ в рантайме**; при проблемах — skip + алерт, не мусор в канал.

### 4.2. Вне скоупа MVP

- Генерация текста/картинок нейросетью в момент слота  
- Instagram/TikTok native (только TG + опционально VK / сайт)  
- Social listening, inbox, influencer CRM  
- Полный self-serve биллинг и публичный signup без онбординга  
- White-label агентств (P1)

### 4.3. Роли

| Роль | Может |
|------|-------|
| Владелец продукта (мы) | Создавать tenant, тарифы, смотреть audit всех |
| Клиент-админ | Проекты, слоты, банк, матрица, test/live |
| Клиент-viewer | Только календарь и отчёт (опционально P1) |

### 4.4. Функциональные требования

**F1. Проекты и каналы**  
- Проект = 1 назначение (TG chat_id или site journal).  
- Привязка токена бота / credentials на tenant.

**F2. Слоты (матрица)**  
- День недели + время (MSK) + label + enabled.  
- Импорт CSV: `день,слот,канал,заголовок,текст[,image]`.

**F3. Банк постов**  
- Запись: `id, title, body, image_path|null, category, cooldown_days, times_used, last_used_at, status`.  
- Ротация: не брать пост, если cooldown не истёк.  
- Запас в днях: `remaining_unique / posts_per_week`.

**F4. Контракт публикации (жёсткий)**  
1. Есть непустой `body` (min_chars настраивается, default 200).  
2. Есть локальный файл картинки **или** срабатывает fallback:  
   - сначала `category` default image;  
   - иначе `channel` default из архива.  
3. Если после fallback картинки нет → **status=skipped**, запись в audit, **не** слать текст без фото (конфиг `allow_text_only=false` по умолчанию).

**F5. Режимы**  
- `test` — только outbox/journal, в TG не слать.  
- `live` — только при `EMPIRE_PUBLISHER_LIVE=1` (или per-tenant flag).

**F6. Tick**  
- Cron / timer раз в 1–5 мин: due slots → publish/skip.  
- Идемпотентность: один external_id на post_id.

**F7. Аудит**  
- Еженедельный отчёт: published, skipped (причины), failed, запас банка (дни), последняя ошибка API.  
- Алерт (TG admin): запас < 14 дней **или** fail ≥ 3 подряд.

**F8. Онбординг**  
- Пакет примеров (matrix.csv + 10 md + 10 images).  
- Чеклист go-live из 7 шагов в UI.

### 4.5. Нефункциональные

- Один VPS; изоляция данных tenant в отдельных store или schema.  
- Логи без секретов.  
- Backup store.json / DB daily.  
- Цель: 30 дней uptime без ручного approve постов.

### 4.6. Критерии приёмки MVP

1. Клиент заливает CSV на 30 постов с картинками → календарь заполнен.  
2. 7 дней live на тестовом канале: 0 постов без картинки; skips только по правилам.  
3. Отчёт за неделю уходит в TG/email.  
4. Второй tenant не видит данные первого.  
5. Документ «как пользоваться» на 1 страницу.

### 4.7. Этапы

| Этап | Срок (фокус) | Результат |
|------|--------------|-----------|
| P0.1 Контракт + fallback | 1 нед | Нет «голого» текста |
| P0.2 Банк + ротация UI | 2 нед | SocialBee-логика |
| P0.3 Tenant + audit | 1.5 нед | Можно вести 2 клиентов |
| P0.4 Лендинг + оферта + 1 пилот | 1.5 нед | Первая оплата или явный отказ рынка |
| **Стоп-кран** | после P0.4 | См. §6 |

## 5. Финансовая модель

### 5.1. Допущения

| Параметр | Значение |
|----------|----------|
| Смесь чека (год 1) | 60% Setup+Банк разово, 40% retainer |
| Средний разово (Setup+Банк) | **70 000 ₽** |
| Средний retainer | **8 000 ₽/мес** |
| COGS на клиента | **1 500 ₽/мес** (VPS доля + саппорт-буфер) |
| Churn retainer | **8%/мес** (база) / 15% пессимизм |
| CAC | Органика + свой TG: **5–15 тыс ₽**/клиент; реклама позже |
| Налог (НПД/упрощёнка ориентир) | **6%** от выручки в модели |
| Время продаж на 1 клиента | **8–12 ч** |

### 5.2. Три сценария на 12 месяцев

| | Пессимизм | База | Оптимизм |
|--|-----------|------|----------|
| Новых клиентов (год) | 3 | 8 | 15 |
| Разовые (Setup+Банк) | 3 × 50k = **150k** | 8 × 70k = **560k** | 15 × 80k = **1.2M** |
| Средние платящие retainer (M12) | 2 | 5 | 10 |
| Retainer выручка (год, грубо) | **~100k** | **~350k** | **~800k** |
| **Выручка год** | **~250k** | **~910k** | **~2.0M** |
| COGS+VPS+налог ~ | ~80k | ~180k | ~350k |
| **Валовая после прямых** | **~170k** | **~730k** | **~1.65M** |
| Часы основателя (dev+sales+ops) | 250 | 400 | 550 |
| Выручка / час | ~1.0k | ~2.3k | ~3.6k |

Retainer год ≈ среднее число клиентов × 8k × ~9 мес эффективного присутствия (упрощение).

### 5.3. Unit-экономика одного клиента (база)

| | ₽ |
|--|---|
| Разово Setup+Банк | 70 000 |
| Retainer 9 мес × 8 000 | 72 000 |
| **LTV грубо** | **142 000** |
| COGS 9 × 1 500 | 13 500 |
| Налог 6% | ~8 500 |
| **Вклад** | **~120 000** |
| CAC (органика) | 10 000 |
| **LTV/CAC** | **~14** |

Даже при пессимизме (LTV ~90k, CAC 20k) LTV/CAC > 4 — **сервисная модель здоровая**.  
Self-serve SaaS 1 990 ₽/мес при churn 10% → LTV ~20k — **нужен другой масштаб**, сейчас нецелесообразно.

### 5.4. Точка безубыточности

Учитывая только **cash** (CAPEX 40k + OPEX 3k×6):

- Достаточно **1 клиента** Setup+Банк 70k → окупание прямых денег.  
- Окупание **времени** (250k внутренняя цена): нужно **~3 клиента** базы (разово+retainer) или **2 крупных** банка.

### 5.5. SaaS-ветка (отложить)

| | |
|--|--|
| Цена | 1 990–4 990 ₽/мес |
| Break-even при OPEX 15k/мес + 40ч саппорта | **~40–80 платящих** |
| Срок до этого без сильного маркетинга | **маловероятно < 18 мес** |

**Решение:** SaaS только после **5+** сервисных клиентов и повторного спроса «дайте доступ без вас».

## 6. GO / NO-GO

### GO, если согласны со всеми пунктами

1. Продаём **Setup + Банк + retainer**, не войну с SMMplanner по цене.  
2. P0 ≤ **130 ч** кода на базе Empire; не greenfield.  
3. До публичной разработки: **5 custdev-разговоров** и **≥2** готовности платить депозит / предоплату.  
4. Пилот: 1 внешний канал **2 недели** live без ручного approve.  
5. Стоп, если за **60 дней** после лендинга 0 оплат и 0 депозитов при ≥20 квалифицированных лидах.

### NO-GO (или отложить), если

- Нужен «полноценный SaaS как Buffer» сразу.  
- Нет времени 8–10 недель даже part-time.  
- Банк контента нечем наполнять (нет ниши и своих витринных каналов).  
- Приоритет Empire сейчас — книга/YT/gdepar CPA сильнее этого потока (см. `05_FINANCIAL_MODEL.md`).
